# First separated work contexts

The user approved the integrated plan and the first context split. Two focused subagents received task-specific briefs and the relevant repository documents, rather than the full conversation history. The primary agent retains camera decisions and integration ownership.

The [integrated design package](../design/README.md) remains the shared authority. These bounded work packets translate the first wave into actionable tasks; they do not open unrelated feature production.

| Work context | Owner | Deliverable |
|---|---|---|
| Camera scene and integration | Primary agent + human creator | [Camera prototype packet](camera_prototype.md) |
| Asset feasibility | Asset view-coverage subagent | [Proxy inventory and angle review](asset_view_coverage.md) |
| P1 interfaces and scenarios | Prototype-contracts subagent | [Contracts](prototype_contracts.md) and [declarative fixtures](fixtures/camera_scenarios.json) |

The camera owner may request revisions to either packet when runtime evidence exposes a conflict. Subagents edit only their assigned files. Shared engine configuration, input actions, and integration scenes stay with one owner.

## Gates for the next split

First run the camera/flat-proxy experiment and settle the supported view range and representation contract. Then fishing, inventory, and environment/director prototypes can proceed in separate contexts against stable interfaces. Story and encounter production follow their integration.

The work packets and fixture file are preparation artifacts, not a playable prototype or an executed engine test suite.
